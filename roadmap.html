Roadmap

Every version a proof.

Shipped means: tagged, with its acceptance gates green in QEMU. Planned means planned — nothing below the line is claimed.

01 · Shipped
  • v0.13–14Persistence — Blake3 write-ahead log, crash recovery: apply → reboot → state intact
  • v0.15–16Trust & contracts — three-stage Ed25519 signature chain; two keys become law
  • v0.17AI workloads — in-cell inference, chat API, MCP tool cells
  • v0.18Preemption & multicore — time slices, four cores, exclusive core ownership as a capability
  • v0.19Observability & audit — per-cell CPU time, log rings, request tracing, the tamper-evident audit chain
  • v0.20SDK & app lifecycle — signed app bundles, one-command install, the OS as a signed CI-built image
  • v0.21Data protection — encryption at rest, a net-free keystore, credentials an app never holds
  • v0.22ACP Console — browser login with roles, RBAC + CSRF on every write, lifecycle, topology, deploy with diff, value-free secrets
  • + HAReplica groups — replicas: N, rolling restarts, gate: never 0 replicas alive
  • + LBService routing — round-robin in the gateways; 3 rollouts under fire, 802 req, 0 errors
  • + bootBoot latency — unattended convergence in 7.4 s, per-phase boot trace
02 · Planned — in this order
  • nextBenchmark vs. Linux — a native cell against a Linux process: latency p50/p99, throughput, syscall/IPC cost. Honest, no cherry-picking; the numbers go here when they exist
  • thenSDK developer experience — from arkctl new to a running contracted cell with as little friction as possible
  • thenArkDB — a database as a contracted cell, benchmarked before claimed. Gated on the Linux benchmark going well
  • laterMulti-node — replica groups spread across Arkane nodes; today HA means one machine
  • laterHardware trust — IOMMU, TPM; boot under 3 s. Required before 1.0

The target today is QEMU — bare metal is a named trigger, not a promise. That sentence is on this page on purpose.
