Arkane OS — a specialised operating system in Rust

    
An operating system
built from isolated cells.

    
Built for three things: security, stability
    and less overhead. A ~13,000-line kernel that almost never changes —
    everything else, from the network to the AI model, runs in
    hardware-isolated cells that update and heal like a server fleet.

  

  







  

  

    
01 · Principle

    
What does not exist cannot be exploited.

    
Run a language model in a bank or a hospital today and it stands
    on thirty years of legacy: four hundred syscalls, shells, dynamic linkers —
    and a kernel that needs patching every month. Arkane starts from the other
    end — from nothing — and only adds what can be proven.
    Isolation is not a check the kernel performs on every operation: it is wired
    into the page tables once, at spawn. Drivers, network and storage live
    in cells — so when they break or need an update, the kernel doesn't.

    
That is the whole bargain: a smaller surface to attack,
    a kernel stable enough to leave alone, and nothing running that you never
    asked for. Security, stability, less overhead — not features bolted on,
    but what is left once everything unnecessary is gone.

02 · Isolation

    
Try to break it.

    
This is the real v0.21 cluster — the same handful of cells around a kernel, each
    with its own page table. Isolation is enforced by the MMU, not by policy.
    Click a cell and watch what happens. Then try killing
    gw-admin — the control plane, which is also the ACP healer.
    And if you want to see where the chain of watchers really ends, kill the
    supervisor first.

    

      
      

        healer online
        ·
        respawns 0
        ·
        drift pending 0
        ·
        kernel restarts 0
      

    

    
Click a cell to crash it. With the map focused:
    ←/→ select a cell, Enter crashes it.

    

    
Crash → HEALER_DRIFT_DEAD → respawn: gw-admin heals
    the drift within moments. gw-admin itself sits on the watch list of a tiny
    supervisor cell that replays the signed boot recipe
    (SYS_CELL_RESPAWN_BOOT) when a watched cell dies — cells that die
    in the meantime pile up as pending drift, and restoring takes noticeably longer: the healer
    must reload and verify its state before it may act. What the acceptance suite proves
    is the persistence cell's kill → respawn; for gw-admin the arm is loaded but has
    never fired outside this simulation — because there is no outside kill switch for the
    control plane at all: the kernel refuses self-stop, and nobody else takes orders. The
    playground lets you do what production won't. Kill the supervisor itself and it
    stays dead — the supervisor has no supervisor (a mutual-supervision pair is on the
    roadmap), and with it down, a dead watched cell stays down too. The chain of watchers ends
    somewhere, and Arkane tells you exactly where.

04 · Law

    
Two keys, one law.

    
The developer signs the shape of a cell into its binary.
    The operator provides the values in the manifest. The kernel enforces both —
    structurally, default-deny, at every spawn. Access exists only as a
    capability: an unforgeable token, derivable and transitively revocable.

    

      
cells/inference · signed ed25519 ✓

      
#[arkane_contract(
    needs(memory = "16MB"),
    needs(share::read = "model"),
    forbid(net::inbound, net::outbound, spawn)
)]

    

    
What is forbidden here is not monitored — it is never wired up.

  







  

  

    
05 · Cage

    
The AI that cannot phone home.

    
A real language model runs inside the inference cell — its own
    no_std engine, token-identical to the reference implementation.
    The only thing it can do is answer whoever called it — network cards exist
    only in the three gateway cells, so every byte in or out crosses one of exactly
    three audited membranes.

    

      
gw-public :8081 · /v1/chat/completions

      

    

    
Why can't it phone home? Not because a firewall says no — because
    the path does not exist. A cell receives exactly what its manifest grants,
    on top of what its signed contract allows. The inference manifest grants memory and
    the model weights — and nothing network-shaped. Since no capability for a network
    card is ever declared, the kernel never wires one up: there is nothing to block,
    monitor, or misconfigure. This is what the operator's manifest looks like:

    

      
manifest.yaml · cell: inference

      
arkane: v1
kind: Cell
metadata:
  name: inference
spec:
  image: prod.images.inference@blake3:9c41…   # signed — contract forbids net
  resources: { memory: 4MB, cpu_shares: 1.0, heap_kib: 16384 }
  shares:
    model: blake3:7c8a…                        # weights, mapped read-only
  capabilities: []
  # no mmio, no port, no endpoint —
  # a path to a network card is never created

    

  







  

  

    
06 · Proof

    
Pull the plug.

    
Every apply is written to a Blake3-chained write-ahead log;
    a persistence cell mirrors the cluster state to its own disk, anchored through a
    double-buffered root pointer the kernel reads at boot. Kill the power mid-flight
    and the next boot replays: every cell, every capability, every model mapping
    comes back — without re-applying anything. This page mirrors that
    mechanism. Cut the power and see what's left.

    
    

    
In the real system this test is called make t4-demo:
    apply → hard kernel reboot → the cluster is still there. It has been part of the
    acceptance suite since v0.14.

  







  

  

    
07 · Audit

    
Prove what ran.

    
Seeing what runs is the easy half: the kernel attributes every
    timer tick to the cell it hit, every cell carries a log ring, and every external
    request gets a trace id that rides the IPC header into each cell it touches —
    arkctl top, arkctl logs --trace.
    The hard half is proving what ran after the fact. So every security-relevant
    event — spawn, stop, crash, capability grant, contract refusal — becomes an
    immutable block in a Blake3 hash chain, where each block's content hash
    is the next block's back-link, mirrored block by block to disk. Verification
    is offline: the auditor needs the drive, not the running system.

    

      
arkctl audit · offline against the mirrored disk

      
$ arkctl audit verify --store store.img --list
audit chain OK: 23 blocks, head seq=22 hash=6b01c4…
seq=5   kind=spawn             cell=1   aux=0x3e8
seq=9   kind=contract-refusal  cell=5   aux=0xc
seq=14  kind=stop              cell=1   aux=0xa

$ printf '\x01' | dd of=store.img seek=571432 …   # flip ONE byte, anywhere in one block
$ arkctl audit verify --store store.img
audit verify FAILED: TAMPER: block seq=4 does not
hash to its stored id (content was modified)

$ arkctl audit anchor --store store.img --key signer.key --out anchor.bin
anchored: seq=22 head=6b01c4… → anchor.bin   # Ed25519, operator key — the kernel never signs

    

    
And the honest boundary, stated exactly: the chain proves tampering
    and gaps after its last verified anchor. An attacker who controls the kernel
    before the first anchor can rewrite the story up to that point. In-system
    anchoring keys arrive with the keystore (v0.21); external anchoring later. Until
    then, this sentence is the precise edge of the claim — not a footnote to it.

    
This is an acceptance gate, run on every merge: flip one byte in
    the mirrored chain — verify names the lying block. Flip it back — the chain is green
    again. Detection is exact, not approximate.

  







  

  

    
08 · Sealed

    
Nothing readable on the disk.

    
The audit chain proves what ran. This proves what it can’t read.
    Every app-data body is encrypted before it is mirrored to disk — XChaCha20-Poly1305
    under a key that lives only in a net-free keystore cell, unlocked once per boot
    and held only in RAM. The acceptance gate is a single command anyone can run:
    strings store.img after a full notes round-trip finds
    no plaintext body. Flip one ciphertext byte and the read fails loudly — an
    AEAD error, never silent garbage.

    

      
the headline gate · run it yourself

      
$ strings crates/arkane-kernel/store.img | grep -c "secret note body"
0   # the note is on disk — as ciphertext

$ arkctl secrets set db-password --value-stdin   # by name, never by value
$ arkctl secrets grant db-password 7             # only cell 7 may read it

    

    
The app never holds the credential. An MCP agent calls a
    token-protected tool through the gateway; the gateway fetches the token from the
    keystore per call and injects it, the target verifies it against its own grant —
    and the agent never sees, sends, or can override it. A fully compromised app can’t
    leak a secret it never had. That is the difference from a container, where the app
    almost always holds its own credentials in an env var.

    
At the edges: the agent gateway can terminate TLS 1.3 (optional,
    off by default — the QEMU dev default is honest plaintext on a LAN), and the
    read-only console gains its first write — stopping a cell — behind a
    per-launch token on top of loopback.

    
The honest boundary, stated exactly: at rest means the disk.
    The kernel’s in-RAM blob table still holds plaintext while the machine runs —
    the same edge as “it runs in QEMU.” And the key hierarchy is real, but
    you are its recovery: lose both the operator key and the exported recovery file
    and the data is gone, by design — no in-system escrow to steal.

  







  

  

    
09 · Get it

    
Three commands, and it runs.

    
Up to here you could only read. This is what the v0.20 line added:
    the whole OS builds as one signed artifact. make image
    produces the kernel binary, the baked-in cells — each individually signed — fresh disks,
    and a manifest that names every baked hash, signed as one Ed25519 unit.
    arkctl image verify checks that receipt offline; the bundled
    qemu-run.sh boots exactly what was verified. No installer,
    no download portal — a repository and a receipt.

    

      
arkane-os · from clone to running system

      

    

    
Installing an app is the same trust decision the kernel makes at spawn.
    A bundle is one content-addressed unit — manifest plus signed cell image — and
    arkctl app install verifies it against the same root-signed
    whitelist the kernel bakes in, refusing before any network is touched. Your own
    cell starts as arkctl new: one crate
    (arkane-sdk), a signed contract,
    arkctl bundle pack. And arkctl
    dashboard is the first picture an outsider gets of the running system — a
    console speaking the exact RPCs arkctl metrics and
    arkctl logs speak, served on loopback only — read-only, with a single
    token-gated write (stop a cell).

    
The honest edges, stated exactly: the image targets QEMU — bare metal
    is a named trigger, not a promise. A fresh checkout generates its own key material; the
    chain — root → whitelist → per-image signature — is real, but you are its root
    (production keys arrive via arkctl keys). A brand-new cell is
    baked in at make image time before install can spawn it by
    hash — uploading images into a running system is deliberately not a path. The CI builds
    these same signed artifacts on every push to main, as provider-neutral stages: switching
    CI vendors is a config change, not a build change.
